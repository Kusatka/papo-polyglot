# Ранбук комплекта ПР 1–3 и ЛР 1–3

## Правила работы

До изменения кода сверять требования, схему и связанные вызовы. После изменения выполнять доступные проверки и записывать результат. В журнале фиксировать решения и их основания, найденные ограничения и следующий шаг. Секреты не публиковать. Для защиты объяснять назначение каждого модуля, вход, выход, запросы и обработку ошибок.

## Карта проекта

`pr1` — инфраструктура пяти СУБД; `pr2` — полный цикл CRUD; `pr3` — модель и воспроизводимые данные; `lab1` — образ Python, общие JWT-функции и gateway. ЛР2 и ЛР3 размещены в `lab1/app/lab2` и `lab1/app/lab3` и запускаются отдельными контейнерами из этого же образа. Материалы защиты находятся в `ЗАЩИТА_*.md` и корневом `ПЛАН_И_РЕЧЬ_ЗАЩИТЫ.md`.

## Требования и критерии готовности

- ПР1: пять СУБД, проверка доступности, данные и логи вне контейнеров.
- ПР2: шесть действий для каждого хранилища, включая удаление самого хранилища; предметная область учебного процесса.
- ПР3: ER, DDL, распределение по пяти хранилищам, обоснование, тестовые данные и диаграмма потоков.
- ЛР1: десять студентов с минимальной посещаемостью лекций по термину и периоду, полные карточки и контекст найденных занятий.
- ЛР2: отчёт о требуемой вместимости аудитории для курса заданного семестра и года обучения, с требованиями к технике; полные данные курса, занятия и число слушателей. Год обучения трактуем как номер курса 1–6; календарный год задаём отдельно для однозначного выбора набора групп.
- ЛР3: по заданной группе для каждого студента и курса число запланированных и посещённых академических часов; только лекции с тегом специальной дисциплины кафедры; одна лекция равна двум академическим часам. Выборные курсы учитывать только для записавшихся.
- Для каждой ЛР: отдельный контейнер, HTTP API через gateway, JWT, C4 и DFD Йордана–Коуда, пошаговый trace, независимая сверка, отчёт и объяснение кода.
