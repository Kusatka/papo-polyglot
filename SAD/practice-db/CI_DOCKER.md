# Проверка целевого Docker-стенда

GitHub Actions workflow `SAD Docker verification` поднимает пять СУБД стенда ПР1, загружает модель ПР3 и запускает gateway с тремя отдельными контейнерами лабораторных. Проверка работает в чистом checkout, создаёт одноразовые учебные учётные данные и случайный JWT-секрет. Локальные .env не загружаются в GitHub.

CI проверяет контрактные тесты API, независимую сверку ЛР1 для двух терминов и ЛР2–ЛР3 для всех курсов и групп. PostgreSQL в этом прогоне — целевая версия 16 из compose. Успех CI подтверждает работу проверенных сценариев через Docker-сеть и шлюз; он не заменяет самостоятельную демонстрацию CRUD ПР2 и проверку веб-интерфейсов.

CI не собирает Docker-логи и не публикует файлы артефактами. Учётные данные создаются для одноразового стенда; реальные секреты использовать нельзя. Файл verify_analytics.json в runner является протоколом Docker-прогона, verify_native.json — отдельного прогона PostgreSQL 18; их нельзя смешивать. Результат запуска доступен по статусу job и выводу тестовых шагов.

Workflow запускается при push ветки Thirtyone с изменениями SAD, а также вручную через Actions после появления workflow в default branch. Пока конкретный запуск не завершился успешно, Docker-проверка остаётся открытой в ранбуке.
