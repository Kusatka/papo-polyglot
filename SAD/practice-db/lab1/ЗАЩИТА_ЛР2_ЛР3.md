# Защита лабораторных работ 2 и 3

## Подготовка

Запускать из `practice-db/lab1`: `docker compose up -d --build`. До этого стенд ПР1 должен работать, а база university_system — быть загружена. Повторная загрузка `pr3/load_all.sh pg` удаляет и создаёт учебную базу: применять только если данные действительно требуется восстановить.

Открыть `http://localhost:8000/docs`, авторизоваться teacher/teacher-pass. Общая схема: пользователь → gateway → отдельный lab2 или lab3 → PostgreSQL. Оба слоя проверяют JWT. За пределами Docker доступен только gateway:8000.

## ЛР2 демонстрация

Получить UUID курса:

```powershell
docker exec practice01-postgres psql -U admin -d university_system -c "SELECT id, name, semester, is_elective FROM lecture_courses ORDER BY name;"
```

В Swagger выполнить `/api/lab2/report`: UUID нужного курса, semester=6, study_year=3, academic_year=2025, trace=true. Здесь academic_year — начало учебного года 2025/2026; год набора группы получается 2023. Показать одно обычное и одно выборное занятие: число слушателей факультатива должно учитывать только записавшихся.

Речь: «Я рассчитываю вместимость аудитории по актуальному составу слушателей курса. Вход — курс, семестр и год обучения; отдельно передаю учебный год, чтобы однозначно выбрать набор групп. PostgreSQL связывает специальность, группы и студентов, а EXISTS учитывает индивидуальный выбор курса. Каждая строка содержит полный курс, занятие, требования к техническим средствам и число слушателей. Это вместимость для общего занятия выбранного потока; фактическое распределение потока по аудиториям является отдельной задачей».

Открыть ROOM_SQL в `app/common/analytics.py`: объяснить LEFT JOIN для нулевого числа слушателей, фильтр active, EXISTS и COUNT DISTINCT. Полный документ занятия включает требование к технике, даже если оно равно «Не требуется».

## ЛР3 демонстрация

В Swagger выполнить `/api/lab3/report`: group_name=БСБО-01-23, date_from=2026-02-09, date_to=2026-05-31, tag=спецдисциплина кафедры, trace=true. Затем задать узкий период и показать, как изменился план. Для 2027 года план и посещение равны нулю.

Речь: «Для каждой пары студент–курс я считаю учебный план и посещение. Отбираю именно лекции, помеченные тегом специальной дисциплины кафедры. План вычисляется по расписанию, посещение — по положительным отметкам журнала. Одна лекция даёт два академических часа. LEFT JOIN сохраняет план даже при отсутствии отметки, а отменённые занятия не включаются. Для факультатива студент должен быть записан на курс. По неделям заданного периода PostgreSQL может отсечь ненужные партиции журнала».

Открыть HOURS_SQL: объяснить отличие JOIN lectures от LEFT JOIN schedule/attendance, фильтр массива тегов `@>`, условие по неделе и умножение на 2. Карточка группы и расчёт выполняются в одном согласованном снимке.

## Подтверждение расчётов

```powershell
python tests/verify_analytics.py
```

Скрипт получает снимок семи таблиц и пересчитывает отчёты обычными Python-циклами. Затем сравнивает каждую пару идентификаторов и значения с HTTP-ответом. Проверяет все курсы, четыре группы, три периода и девять отрицательных случаев. Успех фиксируется в `evidence/verify_analytics.json` только после всех проверок.

Этот документ описывает сценарий защиты. Пока тест не выполнен на работающем стенде, его успешность нельзя утверждать преподавателю.
