# Демонстрация ПР №1–3 и ЛР №1 на ноутбуке

Всё, что показывается, работает в контейнерах Docker. СУБД, их веб-интерфейсы и клиенты
(`psql`, `mongosh`, `redis-cli`, `cypher-shell`) отдельно ставить не нужно: они внутри контейнеров.

---

## 1. Требования к ноутбуку

| Что | Минимум | Комфортно |
|---|---|---|
| ОС | Windows 10 22H2 или Windows 11 (64 бит) | Windows 11 |
| Оперативная память | 8 ГБ (запускать стенд частями, раздел 6) | 16 ГБ (весь стенд сразу) |
| Свободно на диске | 15 ГБ | 25 ГБ |
| Виртуализация | включена в BIOS/UEFI (Intel VT-x / AMD-V) | — |
| Права | администратор (для установки WSL и Docker) | — |
| Интернет | при первом запуске: около 3 ГБ образов | — |

Если на ноутбуке стоит VirtualBox, учти тот же конфликт, что был на ПК: Docker Desktop использует
WSL 2 / Hyper-V. Новые версии VirtualBox с этим работают, старые — нет.

## 2. Что установить

| № | Программа | Зачем | Где взять |
|---|---|---|---|
| 1 | WSL 2 | на нём работает Docker Desktop | PowerShell от администратора: `wsl --install`, затем перезагрузка |
| 2 | Docker Desktop | все СУБД, веб-интерфейсы, шлюз ЛР №1 | https://www.docker.com/products/docker-desktop/ |
| 3 | Git for Windows | Git Bash для скриптов `check.sh`, `load_all.sh`, `run_all.sh` | https://git-scm.com/download/win |
| 4 | Python 3.12 или новее | `tests\verify.py`, `selfwork\rotate_passwords.py`, `pr2\run_all.sh`. Нужна только стандартная библиотека, `pip install` не требуется | https://www.python.org/downloads/ — при установке отметь **Add python.exe to PATH** |
| 5 | Браузер | Swagger UI, Kibana, pgAdmin, Neo4j Browser, Mongo Express, Redis Commander | любой: Edge, Chrome, Brave |
| 6 | Просмотр PDF/Word | открыть отчёты | Edge открывает PDF; Word — по желанию |

Не нужны: Node.js, PostgreSQL, MongoDB и прочие СУБД на самом ноутбуке, python-docx (он нужен только для
пересборки отчётов). Удобно, но не обязательно: Windows Terminal и VS Code (показывать код).

Проверка после установки (PowerShell):

```powershell
wsl --status
docker version
docker compose version
python --version
& "C:\Program Files\Git\bin\bash.exe" --version
```

## 3. Ограничение памяти Docker

Создай файл `%USERPROFILE%\.wslconfig` (на ПК такой же):

```ini
[wsl2]
memory=6GB
```

При 8 ГБ ОЗУ на ноутбуке поставь `memory=4GB` и запускай стенд частями (раздел 6). После изменения:
`wsl --shutdown`, потом снова запусти Docker Desktop.

## 4. Перенос проекта

Скопируй папку `SAD` целиком (около 65 МБ) на ноутбук, например на рабочий стол. Пробелы в пути
допустимы. Файлы `.env` в `pr1` и `lab1` обязательны: в них учебные пароли и секрет JWT.

Данные СУБД не переносятся, их заново создают скрипты. Генерация детерминированная: те же UUID и
тот же журнал посещаемости, поэтому отчёт ЛР №1 должен совпасть с рисунками в отчёте. Это
проверяется `verify.py` (шаг 5.5).

## 5. Первый запуск (около 30–40 минут, большая часть — скачивание образов)

**5.1.** Запусти Docker Desktop и дождись «Engine running».

**5.2.** Стенд ПР №1 (PowerShell):

```powershell
cd "$HOME\Desktop\SAD\practice-db\pr1"
docker compose pull
docker compose up -d
docker compose ps
```

Через 2–3 минуты у всех служб должно быть `(healthy)`.

**5.3.** Данные (Git Bash):

```bash
cd ~/Desktop/SAD/practice-db/pr1 && ./check.sh      # проверки и тестовые данные ПР №1
cd ../pr3 && ./load_all.sh                           # структура и данные ПР №3 во всех пяти СУБД, ~1 мин
```

**5.4.** Шлюз и сервис ЛР №1 (PowerShell). Сборка образа скачивает пакеты Python из интернета:

```powershell
cd "$HOME\Desktop\SAD\practice-db\lab1"
docker compose up -d --build
```

**5.5.** Проверка, что всё сходится:

```powershell
python tests\verify.py масштабирование 2026-02-09 2026-04-19
```

В конце должно быть «ИТОГ: расчёт сервиса подтверждён». Потом открой `http://localhost:8000/docs`
и войди через Authorize: `teacher` / `teacher-pass`.

## 6. Если памяти мало (8 ГБ)

Для показа ЛР №1 хватает трёх СУБД:

```powershell
cd "$HOME\Desktop\SAD\practice-db\pr1"
docker compose up -d redis postgres elasticsearch
cd ..\lab1; docker compose up -d
```

Данные в этом случае загружай по одному хранилищу, пока запущено только оно (Git Bash, каталог
`pr3`): `./load_all.sh pg`, `./load_all.sh redis`, `./load_all.sh es`, при необходимости
`./load_all.sh neo4j` и `./load_all.sh mongo`. Загруженные данные остаются в томах и после остановки.

Остальные службы запускай по одной под конкретный показ (`docker compose up -d neo4j`,
`... mongodb mongo-express`, `... kibana`, `... pgadmin`), лишние останавливай:
`docker compose stop kibana`. Самые тяжёлые — Elasticsearch и Kibana (лимит по 1,5 ГБ).

## 7. Если на месте нет нормального интернета

Образы можно заранее перенести с ПК. На ПК, где Docker уже всё скачал:

```powershell
docker save -o D:\sad-images.tar redis:7-alpine rediscommander/redis-commander:latest mongo:7 mongo-express:1-20-alpine3.19 neo4j:5-community elasticsearch:8.16.0 kibana:8.16.0 postgres:16-alpine dpage/pgadmin4:latest papo-lab:1.0
```

Файл займёт около 8 ГБ. На ноутбуке: `docker load -i D:\sad-images.tar`. Затем шаги 5.2–5.4 без
`pull` и без `--build`.

## 8. Перед защитой

- Подними стенд заранее, минут за 10: Elasticsearch и Neo4j стартуют дольше остальных.
- Перед показом ПР №3 обнови кэш Redis: `./load_all.sh redis` в `pr3` (у ключей TTL до 2 часов).
- Что показывать и что говорить — в `pr1\ЗАЩИТА_ПР1.md`, `pr2\ЗАЩИТА_ПР2.md`, `pr3\ЗАЩИТА_ПР3.md`,
  `lab1\ЗАЩИТА_ЛР1.md`.
- После защиты: `docker compose stop` в `lab1` и `pr1`, затем закрой Docker Desktop. Данные останутся в томах.
